# TomoKV data plane

This document describes the implementation in `src/` in this worktree. It is derived from source, without running the server, benchmarks, gate, or a build. Defaults below are source defaults; build flags and binaries were not inspected. Source references identify the fields and transitions behind each mechanism.

## 1. From key bytes to an executing thread

A key has three identities: its complete bytes, a 64-bit hash, and a physical shard. The executing thread is a fourth, mutable identity. Moving a shard changes the last one; it does not redistribute keys or resize a table.

`FlatStore::hash_key` hashes the **whole key**, including any braces; this is not Redis Cluster's CRC16/hash-tag routing. The default is the project's seeded word-at-a-time hash: initialize `h = 0x9e3779b97f4a7c15 ^ (length * 0xff51afd7ed558ccd) ^ g_hash_seed`, fold each eight-byte word with Murmur3's `fmix64`, fold the remaining four to seven bytes using two overlapping four-byte loads, or one to three bytes using first/middle/last bytes, then apply `fmix64` again. The finalizer uses shifts of 33 and multipliers `0xff51afd7ed558ccd` and `0xc4ceb9fe1a85ec53`. `--hash siphash` selects SipHash-1-2 with two 64-bit secret words instead. Both return 64 bits. Boot asks `getrandom` for 24 bytes; failure or a short read leaves all seeds zero. Persistence loading can restore the saved hash kind and seed material. [Hash implementation](src/store/flatstore.h#L477), [key folding](src/store/flatstore.h#L1924), [boot seed](src/main.cc#L137), [restore](src/main.cc#L232).

Routing consumes the low **14 bits**: `bucket = uint32_t(hash) & 16383`. `Router::owner_[16384]` is a 64 KiB array of atomic 32-bit words, each packing `owner_thread << 16 | shard_id`; `65535` denotes no owner. At boot, `per = 16384 / nshards`, `shard = min(bucket / per, nshards - 1)`. Remainder buckets belong to the last shard. The supported shard count is 1–256, default 16; default shard `s` therefore owns buckets `[1024*s, 1024*(s+1))`. The shard identity in this array is immutable after boot. [Bucket and router](src/core/shard.h#L45), [packing and initialization](src/core/shard.h#L561), [configuration](src/core/config.h#L239), [bounds](src/core/config.h#L769).

Ordinary dispatch actually performs **two indexed atomic loads**, separated by parsing work: `router().shard_of(hash)` relaxed-loads the packed bucket word and extracts its low 16 bits; `Server::worker_of_shard(shard)` acquire-loads the separate `shard_owner_[256]` cache. It does not use `Router::owner_of(hash)` as a combined key-to-thread operation. The key argument comes from `CommandSpec::first_key`; cursor, random-shard, scatter, scripting and connection-local commands have explicit alternate dispatch branches. `Op::key()`'s `argv[1]` convenience method is not the general routing specification. [Ordinary route](src/core/io_loop.h#L5121), [owner load](src/core/server.h#L1896), [Op convenience accessor](src/exec/op.h#L140).

Inside the shard, the table uses **another** `fmix64(hash) & table_mask` for its starting slot. This separates slot choice from the low bits already fixed by routing. Each eight-byte slot contains a 15-bit tag in bits 49–63, tombstone bit 48, and a low-48-bit `KvObj*`. An empty zero word ends a probe; a nonzero word with a null pointer is a tombstone and does not. Linear probing increments and wraps with the mask. Tag equality is only a rejection filter: a hit also requires equal length and complete key bytes. The loop's literal limit is `probes <= cap`, allowing the starting slot to be examined twice when no empty word exists. Distinct keys with identical 64-bit hashes therefore remain distinct records, but share routing, tag and initial probe position. Ordinary owner lookup uses bounded loads for key equality through 32 bytes; longer keys and the foreign-read equality path use `memcmp`. Hash-only auxiliary conflict/expiry structures have different collision semantics, described below. [Slot encoding](src/store/flatstore.h#L580), [index and packing](src/store/flatstore.h#L2260), [lookup](src/store/flatstore.h#L2534), [byte equality](src/base/slice.h#L42).

When the owner is another thread, the parser publishes a `Task{Client*, op_id, shard=-1, scatter=nullptr}` into that owner's producer-specific task lane. The 32-byte task is a handle into the client's ROB, not a copied request or value. Ordinary owner dispatch also uses the inbox when the connection thread and shard owner are the same thread. A fused local read is the explicit bypass, described in section 4. The parser first release-publishes the ROB's dispatch frontier, then pushes the task; a refused push rolls back that publication and leaves the input cursor unchanged, so the frame can be parsed again. It batches the notification once per touched owner per parse pass. [Task](src/core/thread.h#L75), [publication, refusal and notification](src/core/io_loop.h#L5214).

Every executor checks ownership **before store access**. A stale task is posted to the new owner; a full destination lane retains it in `stale_tasks_` for later forwarding. Borrow-release messages receive the same rerouting through `stale_releases_`. This is necessary because a parser can retain a route across a migration. [Execution entry](src/core/ex_loop.h#L2780), [forwarding](src/core/ex_loop.h#L3108).

Migration waits for both execution sides to be quiescent, including retired task frontiers and outstanding deferred work. It reserves destination shard-vector capacity before beginning. `begin_transfer` takes an atomic-flag writer exclusion, validates the entire bucket range, and publishes `Preparing` without changing bucket entries. While execution is stopped, the server moves the shard pointers between owner vectors and rebinds the store's retire sink, including its owner-private QSBR ring and block cache. `commit_transfer` release-stores `Committed`, then release-stores each new packed bucket entry; the server next release-stores `shard_owner_`, finishes the descriptor and updates residency accounting. Readers can see the previous or current owner during that publication interval; forwarding handles the previous answer. The actual slot arrays and records remain at their existing addresses. Transfer returns false for conflicting/invalid ownership, unavailable capacity or failed preparation; there is no recoverable allocation after `Preparing`. [Router transition](src/core/shard.h#L606), [range move](src/core/server.h#L1997), [single-shard move](src/core/server.h#L2054), [sink adoption](src/core/server.h#L1917).

The same transfer does **not** adopt every owner-local pointer: `Shard::notify_pending_` still names the old executor's plain `notify_keyless_pending_` boolean until a later `lb_control_pass()` rebinds it. On a resumed pass, task execution precedes that control pass. A keyless event created in the interval writes through the old pointer; the later repair forces a new-owner drain but does not make the pointer move part of the critical section. This remaining ownership-law violation is detailed first under DIVERGENCES. ([shard.h:165](src/core/shard.h#L165), [ex_loop.h:533](src/core/ex_loop.h#L533), [ex_loop.h:1854](src/core/ex_loop.h#L1854), [notify.inc:403](src/cmd/notify.inc#L403))

## 2. Bytes in, command execution, bytes out

The connection owner performs both parsing and sending. In `2s`, that is an IO thread and shard handlers run on EX threads. In `1s`, each physical thread runs both loops, but **ordinary requests still enter the shard owner's task inbox**, including self-owned requests. Fused self-completion calls back into its IO loop; it does not post a completion to itself. The boot-default schedule is `overlap=0`: fused IFID and EX quanta are 32 operations and WB visits 16 connections. Other compiled schedules interleave batches within these same physical roles: fused overlap 1/2 use 128-operation IFID/EX batches and 64-connection WB batches; split overlap 1 uses its separate IO micro-pipeline. These are loop schedules, not additional network/execution thread stages. [Configuration](src/core/config.h#L293), [geometry](src/core/genthread_pipeline.h#L9), [split geometry](src/core/iopipe_pipeline.h#L17), [actual schedule selection](src/core/io_loop.h#L526), [self-completion](src/core/ex_loop.h#L3210).

### Receive and parse

Each `Client` allocates an initial **16 KiB receive buffer**. IO submits one `IORING_OP_RECV` into its unused tail and sets `recv_armed_`; the kernel owns that raw destination pointer until the receive CQE. `on_recv` clears the flag, adds positive bytes to `rlen_`, and in the coarse loop parses immediately; other schedules nominate the client for IFID. A zero/negative receive closes the connection. Dead clients cannot publish new tasks even if a late CQE contains bytes. Receive rearming happens after the IO service pass has had the opportunity to reset the buffer. SQE starvation leaves the receive unarmed for a subsequent pass. [Allocation and bounds](src/net/conn.h#L62), [submission](src/core/io_loop.h#L1949), [completion](src/core/io_loop.h#L3274).

`resp_parse_t` scans RESP arrays of bulk strings, or simple whitespace-separated inline commands. Its `Slice` arguments point directly into the receive allocation. There are eight inline argv slots; a ninth argument allocates a 16-slot heap array, then doubles as necessary. Default request limits are 1,048,576 array elements and 512 MiB per bulk; the parser also has a limited instantiation for authentication/live protocol limits. Incomplete input does not publish an op. Complete input passes command lookup, arity and connection policy checks before routing. Protocol errors produce an ordered local error and mark the connection closing. Neither successful parsing nor hashing advances `rpos_` until dispatch is committed. [Parser](src/net/resp.h#L65), [argv storage](src/exec/op.h#L121), [parse admission](src/core/io_loop.h#L3997), [errors and command lookup](src/core/io_loop.h#L4063).

The buffer is append-only while any op references it. Growth requires ROB quiescence; compaction additionally requires no armed receive, and buffered IFID preparation also pins it. `read_space` requires at least **2,048 free bytes** for another receive. Its 1 MiB soft limit constrains backlog growth; a single incomplete command at `rpos_ == 0` may grow to `proto_max_bulk_len + 64 KiB`. With no usable tail space, IO stops receiving until the ROB drains. At quiescence it memmoves any incomplete suffix to offset zero; an empty receive buffer grown beyond 1 MiB shrinks to 16 KiB. No per-argument refcount is involved. [Buffer lifetime implementation](src/net/conn.h#L309), [reset](src/net/conn.h#L351).

### Owner GET

1. IO acquires the next ROB slot, fills argv, command metadata, hash and shard, and publishes its dispatch frontier. It posts a 32-byte `Task` into the selected owner's task lane and later raises that producer's notification bit.
2. EX gathers a batch, prefetches initial table slots for still-owned ordinary tasks, rechecks ownership, and executes. The ordinary coarse batch cap is **32**. A task blocked by an older same-connection atomic operation is retained in owner-local deferred state; it does not become a completed reply. Prefetching neither obtains ownership nor validates the record. [Batch handling](src/core/ex_loop.h#L2673), [dispatch deferral](src/core/ex_loop.h#L2894).
3. `cmd_get` calls `Shard::store_find_read`, which performs lookup and hit/miss accounting. Missing/expired keys return protocol null; a non-string returns WRONGTYPE. Integer-encoded strings are formatted to decimal. A normal string is copied into the op's reply sink, except when the owner borrows sufficiently large value bytes. A borrow stores `(pointer, length, shard)` in `Op::zc_*` and increments the store's pointer-keyed borrow registry. Default `zc_min` is **16,384 bytes**, and zero disables this branch. [GET](src/cmd/t_string.cc#L359), [lookup accounting](src/core/shard.h#L192), [threshold](src/core/config.h#L334).
4. EX release-stores `OpState::Done`, then signals the connection owner. The IO owner acquire-observes Done only at the ROB's contiguous completed prefix, stages the reply and retires the op. Reply retirement is not socket completion: staged bytes and borrow descriptors can survive after the ROB slot is reusable. WB submits those staged bytes on the same IO thread. Socket completion advances a separate byte frontier. Sections 5 and 6 specify these two lifetimes. [Done publication](src/core/ex_loop.h#L2983).

For a copied ordinary reply, the countable data movement is receive-buffer argv views, one task descriptor copy at handoff, value bytes copied into `Op::reply`, then into connection staging. The **direct reply** exception removes the last copy for bytes that fit: for the first dispatch of a pass, IO lends the empty fill buffer to an op only if the ROB was empty and nothing was queued to write. EX then writes into that allocation through `Op::direct`, while `direct_len` is published through Done. Overflow continues in `Op::reply`. [Direct admission](src/core/io_loop.h#L5234), [sink fields](src/exec/op.h#L152).

### Owner SET

SET shares receive, parse, routing, task publication, completion and retirement with GET. Its handler interprets the value and options on EX. The three-argument form first tries canonical signed-64-bit integer encoding. Otherwise an ordinary, non-TTL raw value can take `try_overwrite` if its representation, allocation, borrow and concurrency guards permit; rejection allocates a replacement object, copies key/value bytes into it, and replaces the table slot. With the normal read-local build armed, replacement is mandatory. Admission failure discards the new object and emits an error; a failed conditional SET returns null (or the requested old value) without publishing a replacement. SET GET copies its old reply before mutation. [Store helper](src/cmd/t_string.cc#L140), [SET](src/cmd/t_string.cc#L546).

With fused ROB acquisition, `reply_ok` can record a `ReplyCode::Ok` instead of formatting five bytes. IO materializes `+OK\r\n` into its fill buffer at retirement. Split acquisition disables reply codes, so split SET still formats reply bytes on EX. This is a compile-time acquisition choice, although shared WB code retains the code-handling branches. AOF-enabled execution records the owner mutation before Done publication; WATCH, blocking wakeups and notification hooks also run before that publication. [Code gating](src/net/rob.h#L197), [format at retirement](src/net/wb.h#L98), [post-handler hooks](src/core/ex_loop.h#L2973).

Queue `head` advances when an item is copied out; a separate `retired` frontier advances after processing the copied item. Capacity uses head, but migration/teardown uses `retired == tail`. A popped item can therefore free its queue slot while it still prevents execution quiescence. Producer tail and consumer head/retired occupy distinct 64-byte lines, with cached peer indices refreshed only at apparent full/empty boundaries. [Frontiers](src/exec/masked_queue.h#L58), [consume/retire](src/exec/masked_queue.h#L490), [fixed queue equivalent](src/exec/exqueue.h#L105).

Steady completion signalling usually crosses **no pointer queue**. EX records `(IO id, WB slot)` in a batch, executes one sequentially consistent fence after the Done stores, sets idempotent ready bits, and owes at most one wake per newly signalled IO per flush. Without a WB slot it uses `client_in_`. Task notification similarly uses a 128-bit producer mask; `set` first reads the word, then performs a sequentially consistent `fetch_or` only on a clear bit. Consumers exchange nonzero words to zero **before** draining. A producer that creates a notification edge checks whether its peer is parked; only a parked peer needs a ring wake. This avoids one syscall per task, not all atomic RMWs. [Ready completion](src/core/ex_loop.h#L3210), [batch fence](src/core/ex_loop.h#L3274), [notification mask](src/core/signal.h#L299), [wake](src/core/signal.h#L400).

## 3. Records, replacement, resizing and reclamation

### Resident representation

`KvObj` has an **eight-byte header**: one-byte type, encoding, flags and short key length, followed by a 32-bit value length in the default build. A key length of 255 or greater adds a four-byte length after the header. A physical TTL slot, when present, adds eight bytes after that; key bytes follow, then the value representation. `HasTtl` means the slot exists, not that the key is volatile: PERSIST can retain the slot with deadline `-1`. Deadlines are absolute realtime milliseconds; `deadline >= 0 && deadline <= now` is expired. [Header](src/store/kvobj.h#L59), [tail addressing](src/store/kvobj.h#L212), [TTL interpretation](src/store/flatstore.h#L1465).

| Encoding | What the record owns |
| --- | --- |
| `Raw` string | Key and up to **192 value bytes** in the same allocation. |
| `Int` string | Key and an `int64_t` payload in the same allocation; GET formats decimal bytes. |
| `Extern` string | Header/key/pointer allocation plus a separately allocated value block. |
| `Compact` collection | Collection metadata and packed payload embedded in the `KvObj` tail. |
| `Extern` collection | Pointer to a separately managed hash/list/set/zset/stream object. `OwnsExtern` identifies the header responsible for destroying it. |

The object allocation requests the **class-rounded** size explicitly, including on the libc path. `good_size` returns 8 through eight bytes, 16-byte multiples through 128, then four classes per power-of-two interval. Under `TOMO_JEMALLOC`, allocation/free call `mallocx` and `sdallocx`; workers can bind private arenas. Header/value lengths reconstruct allocation size; no capacity word or full hash is stored in each record. A new external string adds a second allocation. Rehash consequently has to hash key bytes again. [Constructors](src/store/kvobj.h#L907), [encoding declarations](src/store/kvobj.h#L45), [class computation and allocator](src/base/alloc.h#L48), [destruction](src/store/kvobj.h#L1285).

Ordinary collection mutations can change their owner-only payload behind a stable header; `note_object_size_change` adjusts accounting by before/after sizes. The foreign lane reads string values only, and never follows a typed collection into its mutable contents. Re-headering an external collection moves its ownership bit to the replacement and restores it on failed insertion. Re-headering strings copies their contents so an old borrowed value stays intact. Thus "all records are immutable" is false; the relevant guarantee is that the string bytes a foreign reader or wire borrower can still observe are protected from in-place mutation in the default build. [Collection accounting](src/store/flatstore.h#L1201), [TTL re-header](src/store/flatstore.h#L3236), [string re-header rule](src/store/kvobj.h#L1143).

### Publication and expiry

With read-local disabled, ordinary SET can overwrite a Raw string only when the key exists, there is no physical TTL slot, the new value is at most 192 bytes, its reconstructed allocation class equals the existing class, and the value pointer has no outstanding borrow. It checks maxmemory admission if enabled. Equal-length overwrite copies only value bytes; changed length also updates the header and accounting. Integer SETs and all rejected raw overwrites allocate a replacement. [Overwrite gates](src/store/flatstore.h#L1244).

With default selector 0 and read-local armed, `try_overwrite_read_local` immediately returns `NotPossible`. An ordinary replacement initializes an unpublished record, release-stores its packed pointer/tag into the slot, then queues the old record for grace-period reclamation. A new insertion and a deletion likewise publish one slot word; deletion stores a tombstone. **A plain one-slot immutable SET does not advance the table generation.** A reader which already loaded the old pointer may return that old complete value even after the slot is replaced. It never reloads the slot merely to demand the newest pointer. [Default rejection](src/store/flatstore.h#L2713), [armed insertion/replacement](src/store/flatstore.h#L3150), [atomic slot store](src/store/flatstore.h#L3340).

Owner `find` can do work beyond reading: advance rehash by one step, resolve an MVCC record, lazily remove an expired physical record, and update eviction metadata when maxmemory is enabled and NO-TOUCH is false. The local lane checks expiry against its copied deadline and falls back when owner-side expiry/notification behavior is needed; it does not delete the object itself. The expiry index records **hashes**, not keys or pointers. Full-hash collisions share this auxiliary registration: they do not merge table records, but volatility counts and active-expiry coverage are hash-granular. Default logical expiry still consults the object's inline deadline; a compile-time deadline-sidecar variant can consult the hash index instead. [Owner lookup](src/store/flatstore.h#L1209), [deadline source](src/store/flatstore.h#L1465), [expiry registration](src/store/flatstore.h#L1950), [hash-only index](src/store/flatstore.h#L133).

### The two-table resize

A new FlatStore normally allocates **1,024 slots**; the minimum capacity is **64**, and capacities are powers of two stored in `uint32_t`. It has two sets of `tab_`, `cap_`, `mask_`, `live_` and `tombs_`: table 0 is current and receives insertions; table 1 is the old table being drained. The maximum representable power-of-two capacity is `2^31`; a request that would exceed the 32-bit capacity representation fails. [Construction](src/store/flatstore.h#L711), [capacity rounding](src/store/flatstore.h#L2251), [fields](src/store/flatstore.h#L3768).

Before an insertion, if `(live[0] + tombs[0] + 1)*100 >= cap[0]*70`, the owner starts rehash. It doubles only if `live[0]*200 >= cap[0]*70`—at least 35% live occupancy. Otherwise it rebuilds at the same size to remove tombstones. Deletion can halve a non-rehashing table when `live[0]*400 <= cap[0]*70`, at most 17.5% live occupancy, subject to the 64-slot minimum. Snapshot preparation suppresses these starts. Allocation of the fresh zeroed array happens before swapping table roles; allocation failure returns insertion failure or abandons optional shrinking. [Grow and shrink thresholds](src/store/flatstore.h#L3644).

Each rehash step examines **eight old slots**, including empty/dead slots. For each live slot it hashes the record's key again, tombstones the old position and inserts its pointer into table 0. Old-table tombstones preserve probe chains. Ordinary lookups search current then old. Inserting a replacement first removes an old-table copy; otherwise deleting the current version could resurrect the old value. When the cursor reaches old capacity, the old array is freed immediately with the lane disabled, or detached and retired through QSBR with it enabled. [Normal step](src/store/flatstore.h#L3691), [armed step](src/store/flatstore.h#L3304), [replacement across tables](src/store/flatstore.h#L2957).

The bound is **eight source slots per rehash-step call**, not eight instructions, probes, keys per command, or a constant latency bound. Each moved record requires hashing and a destination linear probe; a handler may invoke several store operations, and allocating/zeroing the destination is capacity-proportional work. Snapshot capture deliberately freezes old-table movement and preserves positional pre-images; insertion has extra capacity refusal checks while that image is held. [Snapshot-sensitive insertion](src/store/flatstore.h#L1677), [snapshot state](src/store/flatstore.h#L1045).

While local reads are enabled, topology swaps, moves between tables, and each eight-slot rehash batch run inside `ReadLocalTableGuard`. The owner marks the table word open, publishes topology fields/slots with release operations, then closes with a generation increment. Readers snapshot both tables with acquire loads and validate the generation **before calculating a slot from a pointer/capacity pair**, then validate again after lookup/copy. Detached arrays remain allocated through the reader rotation. This protects memory access even when validation eventually fails; a final check alone could not undo an out-of-bounds probe through a mixed pointer/capacity pair. [Armed resize publication](src/store/flatstore.h#L3288), [topology snapshot](src/store/flatstore.h#L3355).

### Two independent reasons an old object can remain allocated

**Wire borrow.** `FlatStore::borrows_` is an owner-only vector of `{value pointer, refcount, retired KvObj*}`. Repeated GETs of the same allocation increment its count; an auxiliary pointer index supports larger borrow sets. With the local lane disabled, replacement/deletion frees immediately unless that exact value pointer is borrowed. A borrowed retired object moves into the registry and contributes to `pending_bytes_`. IO later posts an unborrow message after the applicable send completion. The shard owner decrements the count, frees a retired object at zero, swaps out the vector entry and repairs its pointer index. The last entry also releases the index. A borrow protects an allocation, not the current key binding. [Borrow/unborrow](src/store/flatstore.h#L1385), [ordinary retirement](src/store/flatstore.h#L3628).

**Foreign-reader grace.** Armed stores attach a `ReadLocalRetireSink` to an owner thread's `ReadLocalDeferredQueue`. Its payload ring contains **4,096 entries of 32 bytes**: reclaim-owner pointer, payload pointer, auxiliary size and reclaim callback. A separate **256-entry batch ring** stores `(64-bit stamp, entry count)`. Object removal pushes metadata without freeing or overwriting the object. At drain time, all unsealed entries receive the **old** value of a global sequentially consistent `epoch.fetch_add(1)`. If the batch ring is full, the newest batch is extended and assigned the newer stamp, delaying that batch rather than freeing it early. [Sink](src/store/read_local_reclaim.h#L21), [ring](src/core/read_local.h#L156), [queue entry](src/core/read_local.h#L372), [seal](src/core/read_local.h#L402).

Each participating fused thread publishes the current global epoch at the end of its executor rotation, after its foreign pointers have been consumed. Its `ReadLocalThreadState::tick` is a 64-bit sequentially consistent publication; bit 63 means parked with no foreign pointer. Resume first clears the parked bit while retaining the old tick, then publishes a fresh quiescent tick before another probing pass. A retire batch is reclaimable only if its stamp is **strictly less** than every active thread's tick; parked threads contribute infinity. The scanner checks its last blocking thread first and can stop on a tick `<= stamp`; otherwise it scans all participants and uses their minimum. No per-GET epoch increment, reference increment or publication is required. [Rotation boundary](src/core/ex_loop.h#L448), [tick transitions](src/core/thread.h#L926), [epoch and grace test](src/core/server.h#L586), [park/resume](src/core/io_loop.h#L722).

A **full retirement ring blocks its writer** in `force_oldest_grace`: seal, refresh the owner's quiescent publication, attempt to drain, then `pause` and `sched_yield` until space exists. There is no timeout and no overflow allocation. A thread which fails to advance or park can therefore hold retired memory and eventually stop that owner's mutation path. This is a writer-side grace wait, separate from the local validation/fallback protocol in section 4. At shutdown, after fused threads have joined, the coordinator drains all queued callbacks without a grace scan and releases caches. [Full boundary](src/core/read_local.h#L416), [shutdown drain](src/core/read_local.h#L348), [post-join cleanup](src/core/genthread.cc#L105).

After grace, a reclaimed object is either recycled, freed, or retained for an outstanding wire borrow. `read_local_cache_put` admits only Raw/Int strings, rejects borrowed Raw values, and pushes a free-list node into the **owner's shared block cache**, not a cache physically owned by the shard. The cache has 48 size-class heads, a maximum of 4,096 nodes per class, and total byte ceiling `4096*192 = 786,432` bytes, further limited at each put by the retiring shard's `obj_bytes_`. Its node overwrites the dead allocation with `{next, allocation_size}` only after grace. New armed SETs pop a matching class or call the allocator; allocation failure empties the owner cache and retries once. Clearing a shard also releases that shared owner's cache. Detached atomic values additionally get a chance to enter the MVCC value pool after grace. [Eligibility and ownership](src/store/flatstore_atomic.inc#L1430), [cache bounds and free lists](src/store/kv_block_cache.h#L54), [allocation fallback](src/store/flatstore.h#L1292), [post-grace callbacks](src/store/flatstore.h#L3452).

The combined lifetime is therefore: **remove physical reference → foreign-reader grace → wire-borrow count reaches zero → reuse/free**, except when the borrow ends before grace, in which case grace alone remains. Logical deletion, ROB retirement, socket send completion and allocation reclamation are four separate events.

### Multi-key visibility is separate from physical installation

Cross-shard dispatch uses one public ROB op plus `ScatterState`, whose allocation carves out dense `ShardGroup` records, per-key `{hash, argv index, shard}` records, key-order indices and command-specific result arrays. Tasks carry the same client/op id with an explicit shard and scatter pointer. A group owns a contiguous span of key-order positions; result positions preserve request-key order despite owner completion order. `ValueSlot` can hold null, **1,024 inline bytes**, or a borrowed value pointer/length/shard. Its borrow cutover is additionally controlled by the configured zero-copy threshold. `pending.fetch_sub(1, acq_rel)` identifies the final participant; multi-wave commands post their next owner work through the same task transport. IO emits one ordered reply after the public op becomes Done. [Scatter layout](src/cmd/scatter_engine.inc#L56), [state](src/cmd/scatter_engine.inc#L429), [arena carving](src/cmd/scatter_engine.inc#L771), [completion](src/cmd/scatter_engine.inc#L3659).

An atomic write physically exchanges each key's table pointer **before** the group becomes visible. Each owner prepares a **144-byte `AtomicEntry` header plus `capacity` parked `KvObj*` slots**, with optional copied key bytes/offsets. The entry names its shared group epoch, abort flag and reference counters, origin connection, key span, membership bitmap and installed count. Installation saves the displaced pointer in `parked()[count]` and increments count. A null installed pointer represents deletion. Owner pending entries form an ordered linked list, plus 64 connection-index buckets and size-class pools in `AtomicPendingState`. Physical newest and logically visible are therefore different answers while entries remain linked. [Entry and pending layout](src/store/atomic_mvcc.h#L18), [prepare/install](src/store/flatstore_atomic.inc#L298).

A group epoch of zero is undecided. Commit first increments `atomic_commit_inflight_`, reserves a ticket from `commit_seq_`, release-stores the ticket into the group and publishes its member state. The last outstanding publisher advances `atomic_commit_safe_` monotonically with a CAS. `atomic_snapshot()` reads **safe**, not drawn tickets, so readers need not wait for a writer paused between ticket reservation and publication. IO captures read cuts in parse order while atomic tracking is active; nonblocking, nonwriting ops store a low-32-bit cut in `Op`, reconstructed against a later sequence. Cross-shard reads register a `SnapshotCut`; IO publishes the successor of its minimum inclusive cut as a reclamation floor, then confirms the snapshot publication handshake. A completed gather can release that read protection before reply retirement because copied results or explicit borrows now protect the answer. [Commit publication](src/core/server.h#L2560), [IO cut](src/core/io_loop.h#L4845), [registered floor](src/cmd/atomics_glue.inc#L349), [early completion](src/cmd/scatter_engine.inc#L3712).

The owner resolver filters pending entries by a one-bit membership hint, then compares full hash and key bytes. It reconstructs each key's base and successive candidates from parked predecessors and the physical tail. It skips aborted groups and foreign undecided candidates; committed candidates must have `epoch <= read_cut`, except the connection's own committed writes remain visible for RYOW. The transaction's own undecided candidate outranks committed candidates. When same-connection ticket order inverts, the resolver raises the later record's effective epoch to the earlier record's epoch; equal effective epochs choose the later occurrence. Collapse applies the corresponding order repair before reclaiming old versions. A transaction encountering another undecided unit from its own connection is parked **before its fragment handler starts**, so it cannot turn an abortable predecessor into its own committed write. [Resolver](src/store/flatstore_atomic.inc#L1042), [transaction dispatch hold](src/core/ex_loop.h#L2785).

These MVCC rules govern owner execution. The local lane does not walk the pending list or choose parked predecessors. It either proves its physical read safe with the protocol below or moves the command to owner execution.

## 4. The local-read lane

### Admission is per command; arming is per connection

The lane exists only when `thread_mode == Fused && overlap == 0 && read_local != 0`; `read_local` itself defaults to **0**, so the lane is opt-in. Its defaults, once enabled, are `read_local_prefetch_capture=1`, `read_local_atomic_filter=1` and `read_local_interleave=1`. With `read_local=0`, the fused read-local implementation, per-thread publication state and extended per-store safety state are not allocated. The normal task mesh and FlatStore allocation remain. Only **GET and MGET** carry `ReadLocalEligible`; owner READONLY commands generally do not qualify. The lane can read the local thread's shard as well as a foreign thread's shard. It bypasses ordinary owner task dispatch, not the parser or ROB. [Boot predicate](src/core/server.h#L582), [lane allocation](src/core/ex_loop.h#L196), [defaults](src/core/config.h#L248), [lane default](src/core/config.h#L320), [GET/MGET registration](src/cmd/t_string.cc#L1465).

The connection initially records only its newest write's ROB id. The first attempted local read invokes `Rob::read_local_arm`: no live preceding write changes arm state from 1 to 0; a live unrecorded write changes it to **ArmFence=2**. That fixed fence sends every read to the owner until the pre-arming write id retires. Later writes do not extend this fence. Only the first write **after arming** allocates the 1,216-byte, 64-aligned write-ring sidecar. Allocation failure returns the connection to unarmed tracking; the next read fences the recorded write. Pure reads, pure writes that never attempt a local read, and idle connections allocate no write-ring sidecar. [Arm transition](src/net/rob.h#L829), [first armed write](src/net/rob.h#L473), [allocation](src/net/rob.h#L709).

The armed write ring has **64 `{64-bit hash, 64-bit op id}` slots**, matching the ROB's 64-op window. A 128-byte array mirrors each slot's low-16-bit hash tag; valid/wide bitmaps in the ROB reject impossible matches before reading the exact ring. A point write refines its staged descriptor to a hash. A blind MSET with at most **16 keys** can instead store a two-bit-per-key filter and consult the still-pinned argv for exact hash membership. Other writes retain a conservative overflow generation which conflicts with every read until its newest covered id retires. Ring pruning uses `op_id - flush < dispatch - flush`, not Done state. Capacity overflow is structurally unreachable for 64 live ROB ids but still has a conservative-generation fallback. Identical 64-bit hashes are treated as key conflicts even for different key bytes. [Sidecar](src/net/rob.h#L72), [refinement](src/net/rob.h#L505), [conflict lookup](src/net/rob.h#L573), [prune/overflow](src/net/rob.h#L919).

The parser declines local service for active MULTI, WATCH state, blocked/subscriber connections, incompatible scatter/script/all-shard context, a matching live write descriptor/arm fence, or an unfinished matching owner-routed predecessor. It tests every MGET key for write and atomic-safety conflicts. MGET also declines whenever key-miss notifications are armed, since missing elements need owner notification behavior. A point read sees an open/poisoned table generation or unsafe key before enqueue and declines. Consecutive GETs can reuse stable connection gates, but still test their write/owner conflicts and validate at execution. [Classification](src/core/io_loop.h#L4188), [read eligibility](src/core/io_loop.h#L4344), [decline chain](src/core/io_loop.h#L4398), [MULTI interception](src/core/io_loop.h#L4584).

A local read publishes its ordinary ROB slot, sets a venue-pending bit, and appends a **16-byte `{Client*, op_id}`** to the same thread's local FIFO. The FIFO allocates 1,024 entries plus one fallback-reason byte per entry; admission checks both an effective entry cap and aggregate possible-demotion demand. That demand is 1 for GET and `min(MGET key count, nshards)` for MGET; its ceiling is **1,023**, leaving one normal task credit for a following operation. A full lane or per-connection quota does **not** demote the fresh read: it leaves the frame unconsumed and ends parsing. Pressure starts an eight-rotation fair-share period; during it the connection quota is `max(1, lane_admit_cap / max(1, live_connections))`. MGET waits until that connection has no pending local reads, then sets a ROB fence that stops younger parsing until MGET completes or irrevocably enters owner queues. [FIFO and capacity](src/core/ex_loop.h#L114), [admission](src/core/ex_loop.h#L269), [pressure](src/core/ex_loop.h#L300), [parser backpressure](src/core/io_loop.h#L4451), [publication](src/core/io_loop.h#L5183).

### The exact validation word

The word is `ReadLocalStoreState::probe_sequence`, reached through `FlatStore::atomic_pending_`'s extended allocation. It is **not** the global QSBR epoch or the MVCC commit ticket:

| Bits | Meaning | Writer transition |
| --- | --- | --- |
| 0 | Table mutation bracket open. | Outermost `ReadLocalTableGuard` entry release-stores bit 0 set, followed by an acquire/release fence. |
| 1 | At least one unsafe publication scope/atomic entry, or permanent fail-closed witness. | First pending witness sets it; last nonpoisoned witness clears it. |
| 2–63 | 62-bit table generation. | Outermost bracket exit increments, clears bit 0 and preserves bit 1. At `(1<<62)-1` it saturates and all local probes decline permanently. |

Nested guards use owner-only `table_mutation_depth`; they do not increment on every nested operation. Guards cover topology changes, rehash moves, old-to-current replacement, atomic physical exchange/publication and broad poison entry. They do **not** cover each ordinary immutable single-slot SET or DEL. Thus unrelated ordinary replacements need not invalidate a captured pointer; a table move or atomic bracket does. [State layout](src/store/flatstore.h#L555), [bit layout](src/store/flatstore.h#L626), [transition](src/store/flatstore.h#L3490), [key-scope publication](src/store/flatstore.h#L875).

The comparison is `((after ^ before) & ~kReadLocalPendingBit) == 0`: the pending bit is deliberately ignored. Eligibility separately requires bit 0 clear and a nonsaturated generation. A point probe:

1. Acquire-loads the word, checks key safety, then checks eligibility.
2. Acquire-loads the two pointer/capacity/mask triples and compares the word again **before dereferencing those table snapshots**.
3. Acquire-loads slot words, filters tag and compares complete key bytes, current table before old.
4. Compares the word after lookup; the caller copies the string/decimal response into private reply storage and validates once more before publishing Done.

The capture-enabled batch first prefetches starting slots, then captures each matched **object pointer, deciding slot address and word**; the execution pass uses that captured object, never reloads the slot to adopt a newer object. QSBR protects both object and table allocation through the rotation. GET missing, typed value, expired TTL or unsupported encoding clears tentative output and moves to the owner. Successful local reads **copy values even above `zc_min`**; they do not register a foreign borrow. [Probe](src/store/flatstore.h#L914), [capture](src/store/flatstore.h#L960), [comparison/topology](src/store/flatstore.h#L3344), [reply and validation](src/core/ex_loop.h#L1449).

**Mismatch behavior depends on the actual configured path.** Default capture-enabled GET makes one topology/record attempt: Churn or final validation mismatch breaks to owner fallback. With capture disabled, GET has **three attempts**, continuing after Churn or validation mismatch. Both local MGET implementations have **two whole-command attempts**. Compile-time object-sequence overwrite adds a further copy-validation failure that can retry the captured object's payload within GET's three-iteration loop. The code therefore does not implement a universal "no reader retries" rule. No failed tentative reply reaches WB. [GET retry loop](src/core/ex_loop.h#L1459), [MGET loop](src/core/ex_loop.h#L1170), [captured MGET loop](src/core/ex_loop.h#L1299), [object validation](src/core/ex_loop.h#L955).

### Why pending writes to other keys usually do not disable it

Each armed store embeds `ForeignReadSafety`: **4,096 atomic 64-bit cells**, **4,096 atomic 32-bit cell epochs**, and counters, totaling **49,216 bytes**. Cell selection is `fmix64(hash) & 4095`. The fingerprint is the next 32 mixed bits (`uint32_t(mixed >> 12)`, remapping zero to one). A cell packs a 31-bit count, 32-bit fingerprint and top-bit wildcard. No pending witness means the point probe skips this filter. With the witness set and filtering enabled, a zero cell or nonwildcard fingerprint mismatch proves absence; a hit forces owner fallback. With filtering disabled, any pending witness declines the whole shard. [Filter layout](src/store/foreign_read_safety.h#L22), [point gate](src/store/flatstore.h#L821).

An owner adds **every key occurrence** before unsafe physical work, release-publishes the cell and advances its cell epoch; close decrements and advances again. Two different fingerprints sharing a cell turn it wildcard until the count drains to zero. Count saturation at `2^31-1` retains a wildcard until all unsafe references and poison scopes drain; a total-count overflow permanently poisons all cells. An unenumerable write opens a whole-shard poison scope: the first opens all 4,096 cells as wildcards, nested opens increment only a poison reference, and the last closes each cell. The 32-bit cell epochs wrap; the implementation relies on fewer than `2^32` touches of one cell in a read window, not on saturation. Consequently the filter is conservative, not an exact per-key map. [Add/collision](src/store/foreign_read_safety.h#L195), [close](src/store/foreign_read_safety.h#L238), [poison](src/store/foreign_read_safety.h#L98), [epoch wrap](src/store/foreign_read_safety.h#L224).

MGET opens a **command-wide** window before any value copy. Up to **128 keys** cache hashes/routes and use per-key cell epochs when the filter is enabled; up to **256 shards** are tracked. It snapshots every queried cell's epoch, probes/copies values in request order (captured in chunks of 32 keys), then performs an acquire fence and rereads all queried epochs once. A changed epoch rejects the complete tentative reply. Each individual probe still validates its table topology. Above 128 keys, or with filtering off, MGET uses the legacy whole-shard generation comparison and per-key final validation. Missing MGET elements can return null locally, unlike GET misses; typed or expired elements demote the entire command. Transient failure can rebuild the entire private response once with the same command expiry time. These checks exclude torn **atomic groups**; ordinary independent SETs do not advance the window and do not constitute a multi-key atomic group. [Window](src/core/ex_loop.h#L1008), [captured key chunks](src/core/ex_loop.h#L1299).

### Preserving order when a local attempt moves to an owner

A later same-connection write cannot simply overtake unresolved local reads. `ReadLocalDemotionPlan` selects pending reads matching the write's hash or precise MSET keyset; broad commands select conservatively. It expands the selection to the connected overlap set of pending reads, prepares any required MGET scatter state, counts task credits by owner and reserves those credits before publishing. Selected reads enter owner queues in ROB order **before** the triggering command. If reservation fails, it cancels preparation and leaves the current input unconsumed. If MGET admission stops partway through a prepared prefix, the remaining selected reads retain their fallback reasons for a later pass. [Selection and overlap closure](src/core/io_loop.h#L3500), [publication](src/core/io_loop.h#L3726).

The ROB has separate venue-pending and owner-routed bitmaps. Demotion clears the former, sets the latter and clears any MGET fence only after task publication. Younger reads check unfinished overlapping owner ops; Done entries can leave the owner-conflict bitmap before wire retirement. A successful local batch publishes only its prefix before the first failed member; tentative bytes for the rest are cleared, and the demotion planner decides which overlapping reads must move together. Local processing uses 32-op chunks and, with default interleaving, yields between chunks to queued owner work. [Bitmap edge](src/net/rob.h#L406), [owner conflict check](src/net/rob.h#L424), [prefix completion and fallback](src/core/ex_loop.h#L1681), [bounded interleave](src/core/ex_loop.h#L489).

With maxmemory/eviction enabled, a write classified as precise executes under `ReadLocalPreciseWriteGuard`, temporarily selecting no-eviction so it cannot silently mutate unrelated keys through eviction. Local GETs can also update the five eviction bits in the record's flags: LRU/LFU use atomic metadata operations after a successful read, and NO-TOUCH suppresses them. This means the lane is read-only with respect to value bytes and table ownership, but not literally free of record writes under eviction. [Precise write guard](src/core/ex_loop.h#L85), [guard activation](src/core/ex_loop.h#L2861), [foreign touch](src/core/ex_loop.h#L1132).


## 5. The ordering ring: execution completion is not wire completion

`Client::rob_` is a `Rob<64>`. It contains eight chunk pointers, not 64 inline operations. The parser creates each chunk on its first addressed slot with `new Op[8]`; each `Op` is 336 bytes, so a chunk contains 2,688 bytes of operations and all eight contain 21,504 bytes, before allocator overhead. Slots are never freed individually. Because the index is the monotonically advancing operation ID modulo 64, even a depth-one connection reaches its eighth chunk on its 57th acquired operation. Low pipeline depth does not keep the allocation at one chunk. The 192-byte ROB layout consists of a 64-byte chunk-pointer line, a line beginning with `dispatch_`, and a line beginning with `flush_`; the local-read control words occupy the counters' remaining space. ([rob.h:177](src/net/rob.h#L177), [rob.h:770](src/net/rob.h#L770), [rob.h:1048](src/net/rob.h#L1048), [conn.h:834](src/net/conn.h#L834))

An entry is the whole command execution context: up to eight inline argument `Slice`s or an allocated argument array, command-spec pointer, shard, precomputed 64-bit hash, receive-buffer offset, the low 32 bits of an optional atomic read cut, route/reply flags, 96 inline reply bytes with heap growth, optional direct-output pointer/capacity/length, optional borrowed value pointer/length/shard, a coded-reply tag and signed 32-bit integer payload, and an atomic one-byte state. The arguments refer into the connection's receive buffer. `zc_ptr` is also a tagged sidecar carrier: negative `zc_shard` values distinguish scatter, local cross-shard, blocking, transaction, and notification state from an actual borrowed record on a nonnegative shard. Retirement must resolve those sidecars before treating the field as a wire borrow. ([op.h:32](src/exec/op.h#L32), [op.h:137](src/exec/op.h#L137), [op.h:153](src/exec/op.h#L153), [op.h:218](src/exec/op.h#L218), [wb.h:801](src/net/wb.h#L801))

The parser owns both 64-bit frontiers. `acquire()` tests `uint32_t(dispatch-flush) >= 64`; full means return null and stop parsing before consuming the next frame. Otherwise it resets the selected slot to `Free`, builds the command, then release-publishes `dispatch+1` before publishing the task. A refused task enqueue rolls that last publication back. There is no `Issued` state transition in this implementation: task-queue publication makes work executable; the executor eventually release-stores `Done`. `at(id)` masks the ID and dereferences its chunk without checking that the slot still belongs to that generation. Lifetime safety comes from refusing reuse until retirement and from finishing every task/fragment that can name the slot. It is not supplied by a generation check in the handle lookup. ([rob.h:209](src/net/rob.h#L209), [rob.h:268](src/net/rob.h#L268), [rob.h:761](src/net/rob.h#L761), [io_loop.h:3994](src/core/io_loop.h#L3994), [io_loop.h:5283](src/core/io_loop.h#L5283), [ex_loop.h:2983](src/core/ex_loop.h#L2983))

`drain()` snapshots dispatch with acquire, then starts at flush. It acquire-loads each slot's state, stops at the first value other than `Done`, and invokes the reply-staging sink for each completed prefix entry. After the sink has transferred/copied everything it needs, it optionally shrinks the operation, relaxed-stores `Free`, and advances its local frontier. One release store publishes the new flush frontier for the entire drained batch. A reply capacity greater than 4,096 bytes **or any heap argument vector** triggers `Op::shrink()`, which frees the argument vector and returns the reply buffer to its inline storage. Repeated commands with more than eight arguments therefore allocate their argument vector again on reuse. ([rob.h:739](src/net/rob.h#L739), [op.h:145](src/exec/op.h#L145))

“Retire” means **transfer a completed command's reply into connection-owned wire staging and release its command slot**. It does not mean send the reply, receive a send CQE, release all borrowed record memory, or acknowledge anything to the peer. A blocked oldest command prevents younger replies from retiring even when their executors have finished. A scattered operation owns one public ROB slot and reaches `Done` only when its fragment-completion protocol permits it. The ring imposes order within one connection, including parser-generated errors and local reads. It supplies neither a cross-client order nor atomic visibility across shards; those are separate execution/MVCC mechanisms.

There are three distinct backpressure frontiers. A full ROB holds parsed input in the receive buffer until the oldest unfinished command completes. A full owner-task lane prevents publication of that particular next command even with ROB space. A socket that cannot accept data leaves staged bytes/segments and an outstanding or retried send; the IO thread can still retire completed commands into those staging buffers. The normal-client output limits default to zero, so ROB capacity alone does not bound memory for a client that sends commands while refusing replies. Configured output limits test staged byte accounting and close the connection on a hard excess, or after a sustained soft excess; they do not change ROB capacity. ([io_loop.h:4008](src/core/io_loop.h#L4008), [wb.h:797](src/net/wb.h#L797), [wb.h:867](src/net/wb.h#L867), [server.h:3498](src/core/server.h#L3498), [io_loop.h:7036](src/core/io_loop.h#L7036))

ROB quiescence (`dispatch == flush`) means no published operation still needs its argv or entry. It is necessary, but insufficient, for freeing or moving the connection. `Client::safe_to_release()` additionally requires no prepared pipeline frame, no armed receive, no in-flight send, no outstanding first-contact retire claim, and zero WATCH references. Migration adds its own prohibitions on pending serve work, output, barriers, atomic groups, blocking state, and transaction state. The receive buffer also cannot be moved while the kernel has a receive armed into it. ([conn.h:710](src/net/conn.h#L710), [conn.h:722](src/net/conn.h#L722), [conn.h:309](src/net/conn.h#L309))

## 6. Networking, writeback, and the wire frontier

### Rings, sockets, and publication to the kernel

An IO loop initializes a ring with **4,096 SQ entries**. `Ring::init()` requests `SINGLE_ISSUER | DEFER_TASKRUN | SUBMIT_ALL`; if that initialization fails, it retries with no setup flags, and fails boot if the retry fails. There is no SQ-polling kernel thread requested here. Each IO role has its own TCP listener using `SO_REUSEADDR` and `SO_REUSEPORT`; the default listen backlog is 511. A multishot accept SQE carries the listener's generation rather than a `Client*`; accepted connections get a separately allocated 1,984-byte `Client`, receive storage, a connection ID and an IO owner. TCP adoption sets `TCP_NODELAY`; enabled keepalive sets idle to the configured interval, probe interval to `max(1, idle/3)`, and probe count to three. Unix connections can first cross `client_in_` to another IO owner. ([io_loop.h:88](src/core/io_loop.h#L88), [io_loop.h:163](src/core/io_loop.h#L163), [io_loop.h:1913](src/core/io_loop.h#L1913), [io_loop.h:2385](src/core/io_loop.h#L2385), [io_loop.h:3198](src/core/io_loop.h#L3198), [uring.h:93](src/net/uring.h#L93))

A receive is single-shot, with at most one armed receive per connection. Its SQE names writable space in that client's receive buffer; its CQE names that client and reports a byte count or negative errno. Receives are not buffer-selected or multishot. The normal path asks for a 16 KiB receive-space target, but submits the actual available tail capacity returned by `read_space()`. After completion and command processing, the IO loop can reset/compact/grow at a safe buffer boundary and arm the next receive. An unavailable buffer tail or SQE leaves the connection active for a later pass. ([io_loop.h:1949](src/core/io_loop.h#L1949), [io_loop.h:3274](src/core/io_loop.h#L3274), [io_loop.h:6712](src/core/io_loop.h#L6712))

`user_data = (uint64_t(kind) << 56) | (pointer & ((1ULL<<48)-1))`. The implementation uses **eight kind bits, 48 pointer bits, and eight unused bits**, not the 16 kind bits described in the header comment. Wake, receive, send, listener-generation, shutdown, migration-cancel and persistence CQEs share the ring. `for_each_cqe()` calls handlers and advances the CQ once for the batch. A persistence wait entered inside a callback can temporarily preserve unrelated CQEs in `deferred_cqes_`; the raw-callback accounting prevents redelivering the callback currently on the stack. ([uring.h:60](src/net/uring.h#L60), [uring.h:79](src/net/uring.h#L79), [uring.h:255](src/net/uring.h#L255), [uring.h:282](src/net/uring.h#L282))

Preparing an SQE does not submit it. With deferred task work, ordinary busy passes call `io_uring_submit_and_get_events()` through `submit_and_reap()`, so the kernel both receives submissions and runs completion work before userspace next examines the CQ. Coarse overlap-zero passes do this after work; split IO pipelining can submit after its WB stage and again only if later work produced SQEs. Fused overlap-one/two classifies SEND-bearing rotations and submits them immediately; work rotations without SEND coalesce up to **four rotations**, with a forced-full-SQ submission resetting that budget. This is a rotation count, not a time bound. `Ring::note_pending()` is an empty function: liburing's actual SQ state supplies the pending count. ([uring.h:204](src/net/uring.h#L204), [uring.h:319](src/net/uring.h#L319), [io_loop.h:690](src/core/io_loop.h#L690), [io_loop.h:912](src/core/io_loop.h#L912), [io_loop.h:6538](src/core/io_loop.h#L6538), [genthread_pipeline.h:27](src/core/genthread_pipeline.h#L27))

On SQ exhaustion, `sqe()` calls `submit()` once and tries `io_uring_get_sqe()` again. It can still return null; receive/accept/send callers retain their state and retry later. The header's “never returns nullptr” is stronger than its implementation. Before parking, a loop does an unmasked work sweep, publishes its blocked flag, and rechecks its inbound work. `submit_and_wait(1)` waits for one completion with a **50 ms timeout**; explicit process shutdown has its own poll doorbell. A peer that observes the blocked flag posts `MSG_RING` into the target ring. Standalone executors spin for up to **2,048 empty passes** before their park protocol. An idle fused reader marks itself parked for QSBR before the wait and refreshes its reader tick before resuming probes. ([uring.h:175](src/net/uring.h#L175), [uring.h:232](src/net/uring.h#L232), [uring.h:351](src/net/uring.h#L351), [io_loop.h:704](src/core/io_loop.h#L704), [ex_loop.h:819](src/core/ex_loop.h#L819))

### Completion notification and IO-private writeback

`WbEngine` runs on the connection's IO thread in both modes. “WB” names a phase and an object, not another thread or an executor-side send path. Owner completion makes the ROB slot `Done`; the completion signal only tells IO that looking at that connection can now retire something.

Each IO thread has **1,024 WB slots** and a 1,024-bit `ReadyMask`, stored as 16 atomic 64-bit words aligned to a 64-byte boundary. Established remote completions set the client's bit. `set()` first relaxed-loads the word, then uses a sequentially consistent `fetch_or` only when the bit was absent. The executor orders its earlier `Done` stores before even the load-first skip with a sequentially consistent fence, once per notification batch. IO takes nonempty words with acquire `exchange(0)` before traversing their bits. A local fused completion calls IO's completion callback directly. When the WB slot table is full, the connection uses `client_in_` and `retire_queued_` claim suppression instead. Losing that channel enqueue clears the claim; it does not undo `Done`. ([signal.h:262](src/core/signal.h#L262), [thread.h:1051](src/core/thread.h#L1051), [ex_loop.h:3210](src/core/ex_loop.h#L3210), [ex_loop.h:3253](src/core/ex_loop.h#L3253), [ex_loop.h:3274](src/core/ex_loop.h#L3274))

IO converts either notification into `pending_serve_`, a private `deque<Client*>`. `Client::serve_pending_` suppresses duplicate entries. A serve drains the completed ROB prefix and may prepare a send. A **64-pass/turn backstop** also schedules active clients even if no completion notification arrived; this repairs missed/coalesced notifications and retries buffer/queue pressure. Clients whose input is stopped by a full ROB, whose receive could not be rearmed, or whose output remains pending stay active. The ready bitmap and serve deque contain client identities, never reply payloads. ([io_loop.h:5540](src/core/io_loop.h#L5540), [io_loop.h:6641](src/core/io_loop.h#L6641), [io_loop.h:6800](src/core/io_loop.h#L6800), [io_loop.h:6911](src/core/io_loop.h#L6911), [iopipe_pipeline.h:32](src/core/iopipe_pipeline.h#L32))

### How replies become an ordered byte stream

The usual copied-reply path uses two `SmallBuf<512>` buffers in `Client`: `buf_[fill_]` receives retired replies while `buf_[fill_^1]` is the current send buffer. `wsent_` is a **64-bit** offset into the latter. IO swaps their roles only when the old send buffer is drained and no send is in flight; it clears the old send buffer and resets `wsent_` to zero. This prevents append/reallocation from moving bytes the kernel is reading. ([conn.h:389](src/net/conn.h#L389), [conn.h:421](src/net/conn.h#L421), [conn.h:787](src/net/conn.h#L787), [wb.h:399](src/net/wb.h#L399))

An executor's reply sink can write into an unpublished tail of the fill buffer only when that command was dispatched as the connection's sole outstanding operation with no pending wire output. The operation records `direct_len`; retirement commits those bytes into the fill buffer and appends any spill from `op.reply`. Other copied replies are assembled in the operation and copied at retirement. Fused coded replies defer formatting further: tags 1–9 encode OK, RESP2 null bulk, PONG, null array, empty string, RESP3 null, true, false and an `int32_t`; WB reserves 16 bytes in fill and formats directly there. Split operations keep coded replies disabled. A reply already containing bytes declines a new code, and moving into the segment path materializes any outstanding code first. ([io_loop.h:5234](src/core/io_loop.h#L5234), [op.h:281](src/exec/op.h#L281), [op.h:340](src/exec/op.h#L340), [op.h:61](src/exec/op.h#L61), [wb.h:98](src/net/wb.h#L98), [wb.h:833](src/net/wb.h#L833))

A borrowed GET makes a different stream representation. The executor emits only the bulk header and records `{value pointer, length, shard}` after registering the borrow with the owner. WB first seals any older fill bytes into a copied `Buf` segment, copies this operation's header bytes into another `Buf`, appends a non-owning `Borrow` segment for the value, and appends a static two-byte CRLF segment. Every later reply follows in the same segment queue while it is nonempty; it cannot jump into the ordinary fill/send path ahead of the borrow. ([t_string.cc:394](src/cmd/t_string.cc#L394), [wb.h:807](src/net/wb.h#L807), [conn.h:439](src/net/conn.h#L439))

`SegmentQueue<8>` holds eight descriptors inline and doubles descriptor capacity when it cannot first recover space by shifting live descriptors down. A descriptor contains kind, pointer, 32-bit length, and shard; a head index plus byte offset represents a partially sent first segment. `Buf` payloads are independent `malloc` copies, so moving/growing the descriptor array cannot move an in-flight payload. A `Borrow` owns a release obligation; `Static` owns neither bytes nor a release. The queue has no fixed descriptor-count ceiling or built-in allocation-failure recovery. Its one-input copying overload splits lengths above `UINT32_MAX`; its two-input concatenating overload instead narrows `an+bn` directly into the descriptor's 32-bit length. ([conn.h:115](src/net/conn.h#L115), [conn.h:146](src/net/conn.h#L146), [conn.h:157](src/net/conn.h#L157), [conn.h:239](src/net/conn.h#L239))

Cross-shard MGET retirement builds the array in original key order from `ScatterState::values`, not owner-completion order. Nulls and copied values accumulate in reply bytes. Before each borrowed value it flushes accumulated headers/values as a copied segment, transfers that value's borrow obligation into the client segment queue, appends CRLF, and sets the consumed `ValueSlot::kind` to `Nil` so scatter destruction does not release it twice. Any borrow not transferred, including an error/discard path, is released by `xshard_retire()`. Scatter gathering copies strings of length `<= min(zc_min, 1024)` and borrows longer strings; this is a different threshold from GET's `length >= zc_min`, and `zc_min=0` makes scatter borrow every nonempty non-integer value rather than disabling those borrows. ([scatter_engine.inc:2862](src/cmd/scatter_engine.inc#L2862), [xshard_commands.inc:1719](src/cmd/xshard_commands.inc#L1719), [scatter_engine.inc:3997](src/cmd/scatter_engine.inc#L3997))

Out-of-band frames also respect frame boundaries. `WbEngine::defer_oob()` records the current dispatch frontier and bytes in a per-client deque when a published prefix still needs retirement; frames with the same frontier coalesce into one string. After a drain, entries with `after <= flush` move into the client's stream. A blocked unfinished ROB head has a deliberate exception allowing an out-of-band frame without waiting for that command. These frames are not extra ROB command slots. CLIENT REPLY suppression still drains commands and releases their sidecars/borrows even when their ordinary replies are discarded. ([wb.h:169](src/net/wb.h#L169), [wb.h:320](src/net/wb.h#L320), [wb.h:758](src/net/wb.h#L758), [conn.h:493](src/net/conn.h#L493))

### Sends, completion, and record release

`pump()` permits **one outstanding send per connection** and selects the wire head in this order: remainder of the old ordinary send buffer; existing segments; newly swapped fill buffer. An ordinary send uses `io_uring_prep_send(..., MSG_NOSIGNAL)`. Segments use `io_uring_prep_sendmsg(..., MSG_NOSIGNAL)` with a client-resident `msghdr` and **at most 16 iovecs**. Either request is capped at **`0x7ffff000` bytes**, even if more output is queued. Submission records `segmented_send_`, `send_requested_` and `send_inflight_`; the iovec array and message header remain in `Client` until completion. ([wb.h:395](src/net/wb.h#L395), [wb.h:956](src/net/wb.h#L956), [conn.h:77](src/net/conn.h#L77), [conn.h:503](src/net/conn.h#L503), [conn.h:839](src/net/conn.h#L839))

“Zero-copy” here means **no userspace value copy into reply staging**. Neither send path requests `SEND_ZC`, `SENDMSG_ZC` or `MSG_ZEROCOPY`; there is no separate zero-copy notification CQE. `zc_sends` counts ordinary sendmsg submissions whose iovecs contain a `Borrow`, and `zc_bytes` counts borrowed bytes reported consumed by ordinary send completion. Header construction, copied `Buf` segments, iovec construction, the syscall boundary, and the kernel socket send path still exist. ([wb.h:417](src/net/wb.h#L417), [wb.h:733](src/net/wb.h#L733))

The send CQE clears `send_inflight_`. A positive partial result advances `wsent_` or the segment head/offset by exactly the completed bytes; only finishing an entire `Borrow` segment posts its release. Finishing a `Buf` frees its payload. A short send retains the remainder; EAGAIN/EINTR retries without advancing. A zero-byte result on a nonempty request is treated as a short write and retried, not as EOF. ECONNRESET/EPIPE/ECONNABORTED or an error on a closing client ends the send path as a peer abort; other negative errors count as send errors and close. Depending on the pipeline instantiation, completion either pumps immediately or schedules another IO serve. Completion does not prove the peer application has read the bytes. ([wb.h:585](src/net/wb.h#L585), [conn.h:193](src/net/conn.h#L193), [io_loop.h:2161](src/core/io_loop.h#L2161))

Release goes `WbEngine::release()` → IO's `pending_releases_` deque → current owner's `release_in_` SPSC lane → owner `FlatStore::unborrow()`. The IO callback immediately attempts to flush the deque; a full lane leaves the release at its head and stops that flush. It re-resolves current ownership for every attempted post. A shard that migrated after enqueue forwards its stale release. Even a same-thread fused release uses this owner-release queue, preserving the store's owner-only borrow bookkeeping. After a completed borrow's count reaches zero, a record already removed from the table can finally be freed or returned through the applicable reclamation path. ([wb.h:1049](src/net/wb.h#L1049), [io_loop.h:5523](src/core/io_loop.h#L5523), [ex_loop.h:3143](src/core/ex_loop.h#L3143), [flatstore.h:1385](src/store/flatstore.h#L1385))

### Alternate transport and teardown boundaries

The source also implements an explicitly selected `--net-io epoll` engine. It is not the failed-uring-initialization fallback: that fallback retries uring without flags. Epoll uses edge-triggered client readiness, nonblocking receive/send loops, and synchronous `send`/`sendmsg` returns as the byte-consumption boundary. Its send loop drains until empty or a nonpositive syscall return; it does not hold `send_inflight_` for a future network CQE. Cross-thread wake delivery becomes a mutex-protected tagged mailbox plus an eventfd write, presented to loop callbacks as synthetic CQEs. ([io_loop.h:3204](src/core/io_loop.h#L3204), [wb.h:450](src/net/wb.h#L450), [uring.h:95](src/net/uring.h#L95), [uring.h:366](src/net/uring.h#L366))

TLS has additional plaintext/ciphertext frontiers. Retirement copies any would-be borrowed values into owned segments and returns their borrows; userspace TLS refuses a borrowed segment in its plaintext pump. Plaintext is consumed when OpenSSL accepts it, while ciphertext retains its own buffer and advances on the socket-send completion. A WANT_READ/WANT_WRITE retry pins the same plaintext pointer/length. The kTLS serve specialization likewise suppresses record borrowing. These are separate compile-time serve paths selected for a TLS connection, not extra work imposed on the ordinary non-TLS send. ([wb.h:230](src/net/wb.h#L230), [wb.h:500](src/net/wb.h#L500), [wb.h:635](src/net/wb.h#L635), [wb.h:885](src/net/wb.h#L885))

Runtime close first marks the client closing, cancels deferred/blocking state, and normally calls `shutdown(fd, SHUT_RDWR)` to break outstanding receives/sends. It continues processing completions and execution until the release predicates permit teardown; a requested TLS close-output drain can postpone that shutdown. It clears the ready slot, discards deferred out-of-band state, returns unsent borrows once no send is in flight, closes the fd, and marks the client dead. Actual deletion is deferred through `dead_next_` and `dead_ready_`; pending serve, kernel, and pipeline references extend that delay. A dead client's late send completion consumes any completed bytes and then releases the remaining segments. ([io_loop.h:7143](src/core/io_loop.h#L7143), [io_loop.h:7218](src/core/io_loop.h#L7218), [wb.h:688](src/net/wb.h#L688), [wb.h:703](src/net/wb.h#L703))

Process shutdown is not a guarantee to send every queued reply. Loops stop on the stop condition, worker threads join, owner-only shutdown drains release local-read and atomic retained records, and shutdown reporting inspects remaining work. `Ring::~Ring()` calls `shutdown()`/`io_uring_queue_exit()` to end the ring's kernel lifetime. The wrapper contains a comment promising a coordinator-driven post-join ring fence, but no explicit caller of `Ring::shutdown()` exists in `src/`; destruction is the actual caller. ([uring.h:89](src/net/uring.h#L89), [uring.h:130](src/net/uring.h#L130), [genthread.cc:100](src/core/genthread.cc#L100), [genthread.cc:306](src/core/genthread.cc#L306), [main.cc:351](src/main.cc#L351), [shutdown_report.h:152](src/core/shutdown_report.h#L152))

### The persistence handoff that can delay writeback

With AOF recording enabled, owner execution serializes post-images into `AofProducer::build_`, using **64 KiB chunks**. Sealed chunks enter that shard producer's `ready_` vector; undecided group fragments and later plain records can instead wait in its ordered `staged_` deque. Posting transfers an `AofChunk*` through `AofManager::chunk_in_[producer]`, a **64-entry SPSC channel per physical producer**, to the designated existing writer thread. The chunk carries shard ID, shard sequence, global post sequence, flags, record bytes and optional group-decision state. A full channel returns false and leaves ownership of the chunk in the producer's ready vector. A producer-mask edge wakes the writer. Its ordinary synchronous pass budget is 16 frames; uring/drain-all passes budget 256, and `appendfsync always` caps outstanding uring sync chains at eight. ([aof.h:37](src/persist/aof.h#L37), [aof.h:78](src/persist/aof.h#L78), [aof.h:166](src/persist/aof.h#L166), [aof.h:285](src/persist/aof.h#L285), [aof.cc:611](src/persist/aof.cc#L611), [aof.cc:656](src/persist/aof.cc#L656), [aof.cc:1430](src/persist/aof.cc#L1430), [aof.cc:2041](src/persist/aof.cc#L2041))

Before serving queued replies, IO captures the **global posted AOF sequence** in `aof_gate_target_`. `reply_gate_ready()` requires the durable frontier for `always`, the written frontier for `everysec`, and nothing for `no` or disabled recording. An unmet target returns from the WB pass before taking the pending clients and registers the IO thread for a writer wake. This gate is per IO batch, not per command/key/client: an unrelated client's GET reply can wait for another client's AOF write. Already-executed reads and already-staged sends have different frontiers; the gate is specifically on beginning that batch of reply service. Snapshot capture has a separate execution queue: a write whose pre-image serialization returns `Pending` leaves its task in `snapshot_backlogs_[shard]`. Once that queue is nonempty, later ordinary tasks for the same shard are appended without attempting execution, including unrelated clients' reads. Servicing stops at the first unfinished head. ([ex_loop.h:2523](src/core/ex_loop.h#L2523), [ex_loop.h:2541](src/core/ex_loop.h#L2541), [ex_loop.h:2567](src/core/ex_loop.h#L2567)) ([io_loop.h:6858](src/core/io_loop.h#L6858), [io_loop.h:6245](src/core/io_loop.h#L6245), [aof.cc:1446](src/persist/aof.cc#L1446))

## DIVERGENCES

Ranked by how much the contrary claim changes the reader's model of correctness, ownership, memory, or per-operation cost. These are comparisons with source comments/names and the supplied project laws; no root design, notes or audit document was consulted.

1. **Key-LB still moves a shard without moving its owner-local notification pointer at the ownership edge.** Both transfer functions move membership and the read-local retire sink but leave `Shard::notify_pending_` unchanged. That pointer names `ExLoopT::notify_keyless_pending_`, a plain boolean. Only the post-stage `lb_control_pass()` rebinds it and forces a drain; both fused and split resumed paths can execute tasks before reaching that pass. A keyless notification produced in this interval writes the old owner's flag, which the old owner can independently read/write. This violates the same-critical-section ownership law and admits a cross-thread non-atomic access; eventual forced draining does not establish ownership for the intervening access. Flip has a separate ExInstall binding phase before resume, but the key-LB path does not. ([server.h:2040](src/core/server.h#L2040), [server.h:2069](src/core/server.h#L2069), [shard.h:165](src/core/shard.h#L165), [ex_loop.h:533](src/core/ex_loop.h#L533), [ex_loop.h:755](src/core/ex_loop.h#L755), [ex_loop.h:1833](src/core/ex_loop.h#L1833), [ex_loop.h:1854](src/core/ex_loop.h#L1854), [ex_loop.h:1926](src/core/ex_loop.h#L1926), [notify.inc:403](src/cmd/notify.inc#L403))

2. **The default local-read implementation does retry, and its topology protocol is a per-operation sequence validation.** Both MGET implementations allow two complete attempts. Capture-disabled GET allows three. The default topology word has an open bit, a closing generation increment and before/after comparisons on each local operation; the source itself calls this a “point-probe seqlock comparison.” It protects topology rather than bracketing every immutable SET, but that distinction does not make “no reader retries and no seqlocks on the per-operation path” a literal description of this code. Default captured GET does fall back on its first topology mismatch. ([ex_loop.h:1171](src/core/ex_loop.h#L1171), [ex_loop.h:1300](src/core/ex_loop.h#L1300), [ex_loop.h:1459](src/core/ex_loop.h#L1459), [flatstore.h:3348](src/store/flatstore.h#L3348), [flatstore.h:3508](src/store/flatstore.h#L3508))

3. **Forbidden armed in-place writes remain selectable, and the broken ownership control remains compiled conditionally.** `TOMO_READ_LOCAL_SET_TAX_VARIANT=1` overwrites Raw bytes under the shard sequence; `=3` uses an object sequence and atomic Raw cells. Both are accepted build configurations; neither obeys the ban on in-place overwrite while the lane is armed. Selector 0 is the source default and preserves replacement. Separately, `TOMO_RL_CACHE_NO_EAGER_ADOPT` turns the ownership-edge retire-sink adoption into a no-op, restoring the path where a destination can write through the former owner's private retire ring/cache. Its comment explicitly identifies it as a negative control. These are conditional paths, not evidence that the current binary enabled them; build flags and binaries were outside this reading. ([read_local_settax.h:3](src/store/read_local_settax.h#L3), [read_local_settax.h:29](src/store/read_local_settax.h#L29), [flatstore.h:2768](src/store/flatstore.h#L2768), [server.h:1942](src/core/server.h#L1942))

4. **Read-cut widening does not saturate to an older safe cut.** `op.h` claims that it does. The implementation selects the latest value `<= now` having the saved low 32 bits, with no elapsed-age test or saturation. For example, a stamped cut of 5 reconstructed at `now = 2^32 + 9` returns `2^32 + 5`, newer than the original cut by a full wrap. The stated `<2^31` interval is sufficient, but the claimed behavior beyond the safe interval is absent. ([op.h:165](src/exec/op.h#L165), [op.h:209](src/exec/op.h#L209))

5. **Configured persistence can stall unrelated readers behind writes.** The IO-wide AOF gate can withhold an unrelated GET's reply service until the global written/durable frontier catches up. Snapshot capture can queue an unrelated client's owner-routed GET behind a pending write pre-image solely because their shard is the same. Neither gate restricts waiting to the same connection or conflicting key. The project's “stalls exist only for torn reads and RYOW” statement therefore does not describe these persistence paths. ([ex_loop.h:2541](src/core/ex_loop.h#L2541), [ex_loop.h:2567](src/core/ex_loop.h#L2567)) ([io_loop.h:6858](src/core/io_loop.h#L6858), [aof.cc:1446](src/persist/aof.cc#L1446))

6. **ROB quiescence is not the universal connection-lifetime fence claimed by its header.** The header says teardown tests equality “and nothing else.” Actual deletion additionally waits for prepared frames, kernel receive/send pointers, retire claims and WATCH references; migration has still more state. Treating `dispatch == flush` as permission to free the client would free kernel-visible or callback-visible storage. ([rob.h:14](src/net/rob.h#L14), [conn.h:710](src/net/conn.h#L710), [io_loop.h:7218](src/core/io_loop.h#L7218))

7. **A depth-one connection does not retain one ROB chunk, and ROB fullness does not bound unread output.** The first claim appears at `rob.h:35`; monotonic masked IDs eventually materialize all eight chunks. The second appears at `rob.h:192`; completed operations can retire into growing connection output while the peer refuses to read, and normal-client output limits default off. Those errors change the per-connection memory model from approximately 2.6 KiB of operations plus a bounded window to 21,504 bytes of operations plus independently growing output. ## WHAT SURPRISED ME

- **A connection's ring is also a routing-order index.** Its write descriptors, pending-local bits, owner-routed bits and MGET fence determine whether work may change execution venue; the ROB does much more than order replies. A failed local batch can require transitive overlap closure before anything moves to owner queues. (Section 4; [io_loop.h:3500](src/core/io_loop.h#L3500).)
- **The source makes ordinary replacement invisible to the local validation generation.** Safety comes from retaining the captured immutable object, not comparing the current slot with the captured slot. A reader can validate an old complete value while the table already points to its replacement. Atomic installation and topology movement have different publication rules. (Sections 3–4; [flatstore.h:3150](src/store/flatstore.h#L3150), [flatstore.h:555](src/store/flatstore.h#L555).)
- **Record reuse is tied to three independently moving frontiers.** The object can leave the table, outlive a reader grace period, and still remain borrowed by a send whose command has already retired. The post-grace allocator is owner-wide and a shard clear can empty another shard's reusable class inventory on that owner. (Section 3; [flatstore_atomic.inc:1430](src/store/flatstore_atomic.inc#L1430).)
- **The producer/consumer queue has a third frontier.** A popped task has freed inbox capacity but is still executing; only its later retired frontier permits migration. Queue emptiness alone is deliberately insufficient. (Section 2; [masked_queue.h:58](src/exec/masked_queue.h#L58).)
- **A fused self-owned command normally still crosses an inbox, and a fused self-borrow release does too.** Only self-completion and the qualified local-read lane bypass their respective transport. “One thread does everything” does not describe the number of descriptor operations. (Sections 1, 2 and 6; [io_loop.h:5214](src/core/io_loop.h#L5214), [io_loop.h:5528](src/core/io_loop.h#L5528).)
- **Loop labels conceal retained source, not additional live stages.** Fused `Pipeline==1` and `Pipeline==2` return into private iofused implementations before the older streams scheduling bodies below; those bodies and their context types remain in the file. The live “three-way” label is an intra-thread overlap-two schedule, not the deleted three-thread-stage architecture. `OpState::Issued`, `Ring::note_pending()` and the late sink rebind are three other distinct forms of retained machinery: unused state, empty marker and redundant mutation. ([io_loop.h:526](src/core/io_loop.h#L526), [io_loop.h:781](src/core/io_loop.h#L781), [uring.h:319](src/net/uring.h#L319), [ex_loop.h:457](src/core/ex_loop.h#L457).)
- **The most consequential footprint comments are not enforced by the size locks.** `Rob<64>` really is 192 bytes and `Client` really is 1,984; those assertions say nothing about eventual 64-op materialization, per-store 49 KiB safety state, or output-segment allocations. The locks cover object layout, not total resident memory. ([rob.h:1098](src/net/rob.h#L1098), [conn.h:902](src/net/conn.h#L902), [flatstore.h:555](src/store/flatstore.h#L555).)
